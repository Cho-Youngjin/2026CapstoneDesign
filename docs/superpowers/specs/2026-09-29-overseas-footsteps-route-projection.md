## 1. 개요

체크인 국가를 해외(예: 일본)로 지정하고 실제로는 국내에서 이동해도, 그 이동(방향·거리·시간)을 최대한 유사하게 해당 국가의 실제 도로망 위에 투영해 지도에 그려주는 기능. Google Roads API·Mapbox Map Matching 등 유료/외부 API 대안을 검토했으나, **OSRM만으로 데모 스코프 안에서 구현 가능**하다고 판단해 이 방식으로 설계한다.

### 예시 시나리오

- 체크인 국가: 일본
- 실제 이동: 한국, 양수역 → 운길산역 (도보)
- 목표 결과: 양수역→운길산역 구간의 이동 벡터(방향·거리·시간)를 기반으로, 일본의 실제 도로 위에 "유사한 형태"의 경로를 표시

## 2. 스코프

**포함**
- 데모 대상 국가는 **일본**으로 확정 (2026-09-29)
- 일본의 OSM extract를 사전 다운로드·전처리해 OSRM 인스턴스로 자체 호스팅
- 국내 RoutePoints → 목적국 합성 좌표 → OSRM `/match`로 도로 스냅

**제외 (비목표)**
- 임의의 모든 국가 지원 (Mapbox 등 전세계 커버리지 API 없이는 운영 부담이 너무 커짐 — 국가 확장 시 재검토)
- 실제 경로 모양(교차로 구조, 골목 형태)의 정밀 재현 — 방향·거리 기반 근사로 "그럴듯한" 수준까지만
- GPS 좌표 단위(수 m)의 초고빈도 매핑 — 누적 이동거리 임계값(예: 50m)마다 트리거되는 정도로 충분 (§4 참고)

## 3. 왜 OSRM만으로 되는가

- Google Roads API가 한국에서 안 됐던 이유는 "한국 도로 데이터를 이 API용으로 갖고 있지 않기 때문"이지, OSRM의 한계가 아니다 (`osrm/README.md`, `mock_server.py`의 `snap_to_roads` 주석 참고).
- OSRM은 OpenStreetMap 데이터를 쓰는 오픈소스라 국가 제한이 없다 — 지금 한국 extract를 받아 쓰는 것과 동일한 방식(Geofabrik → `osrm-extract`/`partition`/`customize`)으로 목적국 extract도 받아 전처리하면 그대로 동작한다.
- 지금 도로 스냅에 이미 쓰고 있는 게 `/route`가 아니라 **`/match`(Map Matching) 엔드포인트**다 (`mock_server.py:_snap_via_osrm`, `osrm-routed --algorithm mld --max-matching-size 100`). 즉 "궤적을 도로망에 재정렬"하는 기능은 지금 인프라에 이미 들어 있고, Mapbox Map Matching이 하려던 역할과 동일하다. 별도 API 도입 없이 대상 OSRM 인스턴스만 바꿔 끼우면 된다.

## 4. 핵심 메커니즘

```
[국내 RoutePoints (10m distanceFilter)]
      │  (1) 상대 벡터화
      ▼
[구간별 델타: bearing, distance, elapsed_time]
      │  (2) 목적국 anchor(사용자 선택)에 누적 투영
      ▼
[목적국 합성 좌표 시퀀스 (도로 위 아님)]
      │  (3) 누적 이동거리 ≥ 50m일 때만 트리거
      ▼
      │  (4) 목적국 OSRM /match 스냅
      ▼
[목적국 실제 도로 위 매칭 경로] → anchor 갱신 + 카운터 리셋 → (2)로 반복
```

### (1) 상대 벡터화

기존 국내 RoutePoints(절대 lat/lng 시퀀스)를 인접한 두 점 사이의 **(bearing, distance, elapsed_time)** 델타 시퀀스로 변환한다. 절대 좌표를 버리고 "어느 방향으로 얼마나, 얼마 동안 이동했는가"만 남긴다.

### (2) 목적국 anchor 투영

목적국(일본) 안의 시작 anchor 좌표는 **사용자가 지도에서 자유롭게 선택**한다(국가별 고정 좌표를 두지 않음) — 체크인 플로우에서 "해외 발걸음 시작 지점" 선택 UI가 필요하다. 이후 각 델타를 순서대로 누적 적용해 "허공의" 합성 좌표를 만든다. Haversine 역산(직선거리+bearing → 목적 좌표) 정도로 충분하고 별도 라이브러리 없이 계산 가능하다.

### (3) 트리거: 누적 이동거리 임계값

전체 경로를 미리 계산해두는 배치 방식이 아니라, 사용자가 걸을 때마다 그때그때 매핑한다. 지금 `LocationSettings(distanceFilter: 10)`로 10m 단위 국내 위치 스트림을 구독 중인데(`footsteps_providers.dart`), 여기서 나오는 RoutePoint를 계속 누적하다가 **마지막 anchor 이후 누적 이동거리가 50m를 넘는 시점**에 (1)(2)(4) 파이프라인을 한 번 돌린다(50m 고정값, 2026-09-29). 새 GPS 스트림이나 폴링을 추가할 필요 없이 기존 10m distanceFilter 구독에 누적거리 카운터만 얹으면 된다.

### (4) OSRM `/match` 스냅

트리거된 시점까지 쌓인 합성 좌표 구간을 목적국 OSRM 인스턴스의 `/match/v1/foot/...`에 보낸다. 국내용과 동일한 `_snap_via_osrm` 로직을 재사용하되, 대상 URL만 국가별로 분기한다. 매칭된 마지막 점을 다음 구간의 새 anchor로 삼고 누적거리 카운터를 리셋한 뒤 (2)부터 반복.

**시간 정보**: elapsed_time 델타는 도로 스냅에는 쓰이지 않지만, 지도 위 구분점(탭하면 기록 시각 표시)에 필요하므로 매칭 결과에 원본 타임스탬프를 그대로 이어붙인다.

### (5) 스냅 실패 시 처리 (확정, 2026-09-29)

최초 anchor 선택과 중간 구간 매칭 실패를 다르게 다룬다.

- **최초 anchor 선택 실패**: 사용자가 지도에서 시작 지점을 고르는 즉시(선택 UI 단계) 그 좌표 하나만으로 `/match`를 검증 호출한다. 실패하면(바다·건물 한가운데 등 도로가 없는 지점) 그 자리에서 경고를 띄우고 재선택을 요구한다. 일회성 상호작용이라 막아도 비용이 없다.
- **중간 구간(50m 트리거) 매칭 실패**: 카운터를 리셋하지 않고 계속 누적해서, 다음 트리거 때 더 긴 구간(100m, 150m, …)으로 재시도한다 — 별도 재시도 로직 없이 트리거 자체가 재시도를 겸한다(OSRM `/match`는 궤적이 길어질수록 매칭 후보가 늘어 성공률이 오르는 경향이 있음). 누적 300m를 넘도록 계속 실패하면 그 구간은 합성 좌표(도로 밖)를 그대로 그리되, 지도에서 점선/다른 색 등으로 "도로 매칭 안 된 구간"임을 시각적으로 구분해 표시한다. 롤백(이전 성공 anchor로 되돌리기)은 하지 않는다.

## 5. 인프라: 국가별 OSRM 인스턴스

현재 `osrm/`는 한국 단일 인스턴스(포트 5001, `south-korea.osrm`)만 존재. 확장 방식:

- `osrm/setup.sh`와 동일한 패턴으로 국가별 스크립트(또는 파라미터화) 추가 — Geofabrik에서 목적국 extract 다운로드 → `osrm-extract`(foot 프로필) → `partition` → `customize`.
- `docker-compose.yml`에 국가별 서비스 추가, 포트 분리(예: 한국 5001, 일본 5002) — 데이터 볼륨(`./data/<country>`)도 국가별로 분리.
- 데모 대상 국가가 소수(1~3개)로 고정되어 있어 이 방식의 운영 부담은 감당 가능한 수준. **주의**: 일본 등은 국가 전체 extract가 한국보다 훨씬 크므로, 데모에 필요한 지역(간토/간사이 등)만 지오파브릭의 하위 리전 extract로 좁히는 걸 권장.

## 6. 기존 코드와의 통합 지점

- `app/lib/features/footsteps/data/route_snapping_api.dart` — 지금은 항상 같은 `/api/route/snap`을 호출. 체크인 국가가 해외 데모 대상국이면 요청에 국가 코드(또는 목적국 anchor 정보)를 함께 실어 보내도록 확장 필요.
- `mock-server/mock_server.py`의 `snap_to_roads`/`_snap_via_osrm` — `OSRM_BASE_URL` 단일 값 대신 국가 코드별 URL 매핑(`OSRM_BASE_URL_KR`, `OSRM_BASE_URL_JP` 등)으로 확장. 합성 좌표 생성(벡터화 + anchor 투영) 로직도 별도 모듈 분리 없이 `mock-server` 안에 그대로 추가한다 — Spring(`server/`) 이관은 나중으로 미룸(§8-4).
- 기존 실패 폴백 원칙(스냅 실패 시 원본 좌표 반환) 유지 — 다만 "해외 발걸음"의 원본 좌표는 애초에 국내 좌표이므로, 스냅 실패 시 폴백은 "합성 좌표(도로 밖)를 그대로 그린다"이다. 구체적인 재시도·표시 방식은 §4(5) 참고.

## 7. 한계 / 트레이드오프

- **경로 모양의 근사치**: 방향·거리 기반 투영이라 실제 골목·교차로 구조는 재현되지 않는다. 지도교수 피드백(현실성보다 기술 완성도)에는 부합하지만, 급격한 방향 전환이 많은 구간은 목적국 도로망과 어색하게 매칭될 수 있다.
- **국가 확장 비용**: 국가를 늘릴 때마다 extract 다운로드·전처리·볼륨·포트 관리가 선형으로 늘어난다. 데모 스코프를 벗어나면(임의 국가 지원) Mapbox 등 전세계 커버리지 API 재검토가 필요.
- **사용자가 고른 anchor가 도로에서 먼 경우**: 자유 선택이라 바다·건물 한가운데처럼 도로가 전혀 없는 지점을 고를 수도 있다 — 선택 즉시 검증 호출로 막는다(§4(5)).

## 9. 검증용 도구: 해외 매핑 테스트 (확정, 2026-09-29)

체크인 플로우 전체를 만들지 않고도 §4 파이프라인(벡터화 → anchor 투영 → 50m 트리거 → OSRM `/match` → 실패 처리)을 눈으로 바로 확인하기 위한 개발/데모용 도구. 실제 "해외 발걸음" 체크인 기록으로 저장되지 않는 별도 테스트 세션이다.

**진입**: 발걸음 탭(`FootstepsPage`)의 빈 공간에 **[해외 매핑 테스트]** 버튼 추가.

**동선**:
1. 버튼 탭 → 팝업(다이얼로그)이 뜨고, 그 안에서 **해외 출발 좌표(anchor)**를 지도에서 선택한다 — §4(2)(5)와 동일한 선택 UI·검증 로직(선택 즉시 `/match`로 유효성 확인, 실패 시 재선택 요구)을 재사용한다.
2. 팝업에서 **[동작]** 버튼 클릭 → 팝업이 닫히고 화면이 세로 중앙선 기준으로 분할된다: **왼쪽 = 한국 지도**(실시간 위치·실제 이동 경로), **오른쪽 = 해외 지도**(선택한 anchor부터 시작해, §4 파이프라인으로 실시간 투영·매칭되는 경로). 사용자가 실제로 걸으면 왼쪽은 평소 발걸음 지도처럼, 오른쪽은 50m마다 매칭 결과가 갱신되며 같이 자라난다.
3. **[멈춤]** 버튼 클릭 → 테스트 세션 종료(위치 구독 해제, 상태 초기화), 평소 발걸음 화면으로 복귀. 기록은 저장하지 않는다.

**구현 메모**: 좌/우 지도 모두 기존 `base_google_map.dart`(plan-c에서 지도 초기화·카메라 이동 로직을 재사용 가능하도록 분리해 둔 위젯) 재사용. 화면은 `Row` + 두 `Expanded` 지도 위젯 + 가운데 구분선으로 구성.
